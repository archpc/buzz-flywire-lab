# Publication audit, 2026-10-24

Read-only review of code, datasets, reports and logs before publication. Accepted datasets
were NOT modified. Report errors are corrected in place in `docs/`, each with a dated note.

## Errata (report claims the data does not support)

1. **report_phase5 §2: "Monotonic dose-response in every seed."** False for seed 12347:
   0.3 → 77 MN9 spikes, 0.5 → 74. The other two seeds are monotonic. Corrected.
2. **report_phase5 §8: banana "administered as a 1.0-strength sugar drive."** No 1.0 trial
   exists. The highest level run was 0.5 (`data/banana_peel.json`, `levels`). Corrected.
3. **report_phase5 §2: grooming "0-3.8 Hz resting band."** Max recorded `groom_post` is 3.9 Hz
   (seed 12345, strength 0.0). Corrected. Not material.

## Dataset provenance caveat (dataset not modified; corrected in sidecar)

4. `data/banana_peel.json` top-level `shuffle_seed` reads `0`. The file merges two arms, and
   the metadata came from the last run, which was the intact arm. The shuffled arm used
   `0xC0FFEE` (12648430). This is confirmed independently by that run's bridge log
   (`Spawning kernel: ... --serve --shuffle 0xC0FFEE`, 2026-10-19 00:31:20) and by
   report_phase5. The correction and a per-dataset seed table are in
   [data/PROVENANCE.md](../data/PROVENANCE.md). All other datasets' seed metadata was
   checked and is consistent.

## Evidence-strength notes

- MN9 first-spike latency is weak evidence. Seed 12347 spikes at 1 ms even with no stimulus,
  so the "latency decreased" claim rests on 2 of 3 seeds.
- n = 3 seeds per arm. The seeds are baseline draws on one deterministic model, not biological
  replicates. Shuffled controls: 3 seeds for feeding, 3 for escape.
- MN9 is a single neuron mapped from the reference model's annotation. SiliconFly's own
  cell-type table doesn't tag it.
- Escape latencies (3-5 ms) sit at a calibrated floor. Real flies take tens of ms. This is
  consistency, not prediction.

## Integration defects

- After the lab directory moved, 11 scripts still hardcoded the old location. Fixed: paths
  are now relative to the script location (`BUZZ_HOME` overrides for `buzz.py`). Verified by
  a live `buzz start` and a replay of a recorded trial (seed 12345, strength 0.5: MN9 82 = 82
  recorded, GF 0 = 0), followed by `buzz stop` with `lingering_pids: []`. All four
  `analyze_*.py` scripts regenerate figures and summary numbers from `data/`.
- `docs/API.md` omitted `/ablate`, `/ablate_clear`, `/set_input`, `/stim_trial` and `/export`.
  Updated.
- `GET /read?last_step=1` (as previously documented) returns 404. The bridge only routes the
  bare `/read`, which always includes `last_step`. Documented, not changed.
- `buzz.py`: `--port` must come before the subcommand (`buzz.py --port 8081 start`), and
  `--shuffle` takes a decimal integer (`12648430`, not `0xC0FFEE`). `LAB_SHUFFLE` on `lab.py`
  accepts hex.
- `/shutdown` can hang without reaping the kernel child process. `buzz.py stop` sweeps
  leftover processes.
- **Found by fresh-clone testing after first publication:** `buzz.py`'s process sweep
  (pgrep/pkill) was hardcoded to `drosophila/lab.py` and `drosophila/specimen/...`. In any
  other checkout path, `stop` reported `"lingering_pids": []` while lab.py and the kernel were
  still running (a false "clean" report). Fixed: the patterns are now built from the script's
  own resolved location and regex-escaped. Verified from a clone outside any `drosophila/`
  path: new pattern matched both live PIDs, old pattern matched none, and `stop` left zero
  processes.

## Unaccepted work

- Maze experiments: the open-loop T-maze 10/10 is a reflex readout (the stimulus side encodes
  the answer). Closed-loop smoke runs mostly time out with 362-2464 collisions. No report;
  nothing accepted.
